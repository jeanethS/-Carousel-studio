PASO 1 · CLASIFICACIÓN DE RIESGO Y VALIDACIÓN

Local vs API externa. No todas las tools son iguales.

Para el LLM, leer un JSON local y ejecutar un webhook externo son solo llamadas a funciones. Para tu arquitectura, el radio de impacto es radicalmente distinto.

RISK = {"read_file": "LOW", "spotify.play": "HIGH"}

def call_tool(name, args):
    validate(args, SCHEMAS[name])
    if RISK[name] == "HIGH":
        rate_limit(name)
    return TOOLS[name](**args)

OWASP TOP 10 LLM · EXCESSIVE AGENCY

El riesgo no vive en la alucinación. Vive en la ejecución.

Una respuesta incorrecta es molesta. Una acción incorrecta borra datos, gasta dinero o expone secretos.

Best practice
  • Presupuesto de acción: max_iterations=5 por sesión.
  • Sanitiza la salida de cada tool antes de devolverla al modelo, evita prompt injection inverso.

PASO 3 · MÍNIMO PRIVILEGIO (JIT)

OAuth es arquitectura, no solo configuración.

Las variables de entorno estáticas con acceso total son una bomba de tiempo en agentes autónomos.

Best practice
  • repo:read vs repo:write, scopes segregados.
  • Tokens de vida corta (TTL < 15 min), generados just-in-time.
  • Revoca el token al terminar la ejecución.
@katsi 04 / 08
PASO 4 · ZERO TRUST MULTIAGENTE

Delegar no es confiar. Asegura las fronteras.

En un enjambre de agentes, tratar los mensajes de un sub-agente como confiables es una vulnerabilidad crítica.

Best practice
  • Valida cada payload inter-agente con Pydantic.
  • Un agente investigador ni siquiera debe conocer delete_database.
@katsi 05 / 08
PASO 5 · HUMAN IN THE LOOP ROBUSTO

Exige fricción controlada antes de la acción sensible.

Automatización total es inaceptable para acciones destructivas, financieras o que toquen datos personales.

Best practice
  • Propuesta → aprobación → ejecución. El agente solo devuelve el plan.
  • idempotency_key en cada acción, con rollback definido.

PASO 6 · MINIMIZACIÓN DE DATOS CON KATSI

La mejor defensa es menos contexto.

No subas todo tu workspace a un LLM en la nube. katsi es un MCP local-first: recupera solo los fragmentos relacionales necesarios (decisiones, convenciones, bugs), tus datos no salen de tu máquina.

GUÁRDALO PARA TU PRÓXIMO AGENTE

Cada capability nueva necesita un control nuevo.

Diseña los permisos antes de escribir los prompts.

  • Cada tool tiene validación de esquema y nivel de riesgo.
  • Las credenciales son de corta duración y con scope mínimo.
  • Las acciones de alto riesgo piden confirmación con idempotency_key.
  • El contexto sensible se gestiona local-first, con katsi.
